# 경량 검증 (Fast-Track Verify)

기존 검증 결과(미구현, 구현 불일치 등)가 현재 기획 및 코드 상태에서도 여전히 유효한지 빠르게 판별한다. 이 스킬은 코드를 수정하지 않는다 — 보고만 한다.

## 방어 로직

호출 시 기존 검증 결과 데이터(테이블)와 기획 문서 경로가 입력으로 제공되지 않으면, 아래 메시지를 출력하고 즉시 중단한다:

> "fast-verify-impl은 기존 검증 결과 데이터가 필요합니다. 일반 검증을 원하시면 `/verify-impl`을 실행해주세요."

## 입력

- 기존 PROGRESS.md에 있던 검증 결과 섹션 전체 (`#### 미구현`, `#### 구현 불일치`, `#### 기획 외 제거` 테이블)
- 기획 문서 경로

## 동작

1. 전체 기획 문서를 읽지 않고, 입력받은 테이블의 **"기획 섹션" 열을 참고하여 기획 문서의 해당 섹션 내용만 발췌**하여 읽는다
   - 기획 변경으로 섹션 번호나 제목이 변경되었을 수 있으므로, 요구사항 요약의 문맥을 함께 참고하여 유연하게(Fuzzy) 매칭한다
   - 매칭 실패 시 해당 항목을 "여전히 유효함"으로 보수적 판정한다
2. 발췌한 기획 내용과 현재 코드베이스를 대조하여, 각 항목이 "해결됨(Resolved)"인지 "여전히 유효함(Still Valid)"인지 판별한다
   - `#### 미구현` 항목: 해당 요구사항이 코드에 구현되었는지 확인
   - `#### 구현 불일치` 항목: 기획과 코드의 불일치가 해소되었는지 확인
   - `#### 기획 외 제거` 항목: 기획에 없는 코드가 여전히 존재하는지, 또는 기획 변경으로 해당 코드가 정당화되었는지 확인
3. 기존 항목의 "대상" 컬럼 값(`서버` / `프론트` / `서버+프론트`)은 원본을 그대로 보존한다. 재판정하지 않는다

## 출력

여전히 유효한 항목들을 `progress-tracking.mdc` "하단 섹션 타입" 규칙과 동일한 포맷으로 섹션별 구분하여 반환한다.

해당 섹션 타입에 유효 항목이 0건이면 해당 섹션을 생략한다. 모든 섹션 타입에서 유효 항목이 0건이면 "모든 기존 이슈가 해결되었습니다"를 반환한다.

## 금지 사항

- 코드를 수정하는 것 — 이 스킬은 보고 전용이다
- 발견된 이슈를 임의로 "사소하므로 무시"하고 생략하는 것
