# 기획 변경 정합성 체크

기획 문서 변경의 파급 효과를 분석한다. 교차 도메인 정합성과 PROGRESS.md 동기화를 검증한다.

### 참조 문서

본문에 기술되는 문서는 아래 테이블을 참조해 읽는다.

| 문서 | 참조 방법 |
|------|-----------|
| `progress-tracking.mdc` | rule |
| `review-guide.md` | `review-planning` 스킬의 별도 문서 |
| `write-planning` | 스킬 |

## Phase 1: 변경 수집

입력에 따라 분기한다:

- **커밋 해시 있음** → `git diff {hash}^..{hash} -- docs/`
- **커밋 해시 없음, 파일 지정 없음** → `git diff HEAD -- docs/`
- **파일 지정** → `git diff HEAD -- {파일}`. diff가 없으면 파일 전체를 Phase 3-2의 입력으로 사용

`docs/PROGRESS.md`, `docs/*/@index.md` 변경은 별도 분류한다.

## Phase 2: 변경 분류

각 변경 파일을 아래 형식으로 분류한다:

| 파일 | 도메인 | 문서 유형 | 변경 유형 |
|------|--------|----------|----------|

- **도메인**: `logistics` / `nursing-hospital` / `admin` / `common`
- **문서 유형**: 개요 / 하위 / 분리 / 공통. 판별은 `progress-tracking.mdc` "@index.md 동기화 > 제외 대상 판별" 규칙을 따른다.
- **변경 유형**: 추가 / 수정 / 삭제

## Phase 3: 변경 항목 추출 및 정합성 분석

### 3-1. 관련 문서 수집

각 변경 파일에 대해:

1. **동일 도메인 관련 문서**: `review-guide.md` "관련 문서 수집 규칙" 적용
2. **교차 도메인 대응 문서**: 각 도메인의 `@index.md`를 읽어 카테고리 헤딩을 비교하고, 변경 파일이 속한 카테고리와 동일한 카테고리의 타 도메인 문서를 수집.(카테고리가 동일하더라도 타 도메인의 카테고리 명칭이 다를 수 있음에 유의)
   - 예: 변경 파일이 `logistics/@index.md`에서의 "주문 관리" 카테고리에 속함 → `nursing-hospital/@index.md`의 "물품 관리", `admin/@index.md`의 "주문·배송 관리" 문서 수집

### 3-2. 변경 항목 추출

diff가 있으면 변경된 정책/규칙/수치를, diff가 없으면(파일 지정 모드) 파일 내 주요 정책/규칙을 개별 항목으로 추출한다.

| 항목 | 유형 | 내용 | 출처 |
|------|------|------|------|

- **추가**: diff에서 신규 항목. "내용"에 추가된 값 기재
- **수정**: 기존 값이 변경된 항목. "내용"에 `변경 전 → 변경 후` 기재
- **삭제**: 제거된 항목. "내용"에 제거된 값 기재

### 3-3. 항목 단위 대조

추출된 각 항목에 대해, 3-1에서 수집한 문서 내에서 동일 개념을 서술하는 위치를 찾고 항목 대 항목으로 대조한다. `review-guide.md` "분석 관점 체크리스트"를 적용한다.

## Phase 4: PROGRESS.md 동기화 검증

실행 조건이 모드에 따라 다르다:

- **커밋 모드**: 항상 실행
  - PROGRESS.md 변경 있음 → 아래 검증 수행
  - PROGRESS.md 변경 없음 → "동기화 누락" 보고
- **작업 중/파일 모드**: PROGRESS.md가 diff에 포함된 경우에만 실행. 없으면 건너뜀

검증 항목:

1. `write-planning` 스킬의 "PROGRESS.md 동기화" step의 분류 테이블 기준으로 검증
2. 개요 페이지 변경 시 전파 분석이 수행되었는지 확인
3. amended 판정이 `progress-tracking.mdc` "amended 판정" 기준에 부합하는지 확인
4. 누락된 amended 전이, 비고 기록, 하단 섹션 처리가 있으면 보고

## Phase 5: 보고 및 처리

### 5-1. 기획 이슈 (사용자 확인 후 처리)

분석 결과를 카테고리별로 보고한다:

- **충돌 사항**: 변경 내용이 다른 문서와 모순
- **전파 누락**: 개요/공통 변경이 하위/참조 문서에 미반영
- **교차 도메인 불일치**: 동일 기능의 타 도메인 기획과 불일치
- **부족한 사항**: 데이터 생명주기 등 관련 기획이 존재하지 않음

이슈가 없으면 "분석 완료: 이슈 없음"으로 보고한다.

이슈가 있으면 `AskQuestion`으로 각 항목 처리 방향을 확인한다:

- **충돌/불일치**: 어느 쪽 내용을 따를지 선택지 제시
- **전파 누락/부족**: "기획에 추가: {내용 요약}", "현재는 불필요(Skip)", "추후 결정(TBD)" 중 선택

확인된 항목은 `write-planning` 스킬을 읽고 그 규칙에 따라 기획 문서를 수정한다.

### 5-2. PROGRESS.md 동기화 (자동 실행)

Phase 4에서 누락 또는 오류가 발견된 경우, 누락/오류 사실을 알린 뒤 사용자 확인 없이 `write-planning` step 10을 자동 실행한다.
