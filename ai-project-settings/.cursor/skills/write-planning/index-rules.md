# @index.md 목차 및 문서 구조 규칙

## @index.md 목차 규칙

@index.md에 책 목차처럼 모든 기획 문서 링크를 번호 체계로 정리

### 번호 체계

- 상위 문서: `1.`, `2.`, `3.` ...
- 하위 문서: `1-1.`, `1-2.`, `2-1.` ...
- 각 항목은 해당 md 파일의 상대 경로 링크를 포함한다

### 카테고리 구분

- `### 카테고리명`으로 도메인별 섹션을 구분
- 목차 마지막에 `### 비고` 섹션을 두어 공통 참조 문서를 모은다

### 목차 예시

```markdown
## 목차

### 주문

1. [주문 프로세스](./order/order-flow.md)
  1-1. [상품 목록](./order/product-catalog.md)
  1-2. [주문 내역](./order/order-history.md)

### 배송

2. [배송 관리](./delivery/delivery-management.md)
  2-1. [배송 추적](./delivery/tracking.md)

### 비고

- [로그인/인증](./auth.md)
```

## 번호 체계 관리 규칙

- 번호는 **@index.md에서만** 부여하고 관리한다
- 개별 문서의 제목과 파일명에는 번호를 포함하지 않는다
- 문서를 생성하거나 수정할 때는 반드시 @index.md의 번호 체계를 먼저 확인하고 따른다
- 문서가 중간에 추가되면, 추가 위치 이후의 기존 문서 번호를 @index.md에서 재정렬한다

## 카테고리 분류 규칙

- **도메인/기능 영역** 기준으로 분류한다 (예: 주문, 배송, 정산, 재고)
- 폴더명은 카테고리의 kebab-case 영문명을 사용

## 문서 분리 및 폴더 생성 규칙

- 페이지(기능) 단위로 md 파일을 분리하며, 파일명은 kebab-case를 사용
- 하위 문서가 1개뿐이면 `docs/` 루트에 단독 파일로 둔다
- 하위 문서가 추가되어 동일한 도메인의 파일이 2개 이상이 되면 `docs/<도메인>` 폴더를 생성해 상위, 하위 문서를 모두 해당 폴더로 옮기고, @index.md 링크도 함께 갱신
