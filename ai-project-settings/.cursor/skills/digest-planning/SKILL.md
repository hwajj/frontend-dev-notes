# 기획 요약 (Digest Planning)

기획 문서에서 **사람이 판단해야 할 핵심 사항**만 추출하여 채팅에 보고한다. 파일을 수정하지 않는 read-only 스킬이다.

## 1. 기획 문서 탐색

1. `docs/` 하위의 모든 `@index.md`를 읽어 도메인별 목차를 파악한다
2. 사용자 입력과 목차 항목을 매칭한다
   - 계층 구조 활용: "주문 상세" → 도메인 → 항목
3. 후보가 2개 이상이면 `AskQuestion`으로 사용자에게 확인한다
4. 일치 항목이 없으면 `AskQuestion`으로 문서 경로를 직접 요청한다
5. 매칭된 문서 + 아래 관련 문서를 함께 수집하여 읽는다
   - 상위 문서(개요) 1개
   - 본문에서 직접 링크로 참조하는 공통 문서
   - 해당 페이지와 데이터를 주고받는 형제 문서 (예: 목록↔상세)
   - `@index.md` '공통 문서' 섹션은 본문에서 참조할 때만 읽는다

**도메인 단위 요청 시:** `@index.md`에서 해당 도메인의 모든 하위 페이지를 대상으로, 페이지별로 §2~§4를 반복한다. 공통 정책은 최상단에 한 번만 보고한다.

## 2. 핵심 사항 추출

수집된 문서에서 아래 4가지 관점으로 분류 추출한다.

### A. 비즈니스 정책 (규칙과 제약)

- 상태 전이 규칙 (무엇이 허용/금지되는가)
- 조건 분기 (어떤 조건에서 어떤 결과가 나오는가)
- 권한/역할별 차이
- 확정된 결정사항 (결정 이력 섹션이 존재하는 경우)

### B. 사용자 경험 (동선과 의도)

- 사용자가 보는 화면 흐름 (진입 → 작업 → 완료/이탈)
- 핵심 액션 (무엇을 클릭하면 무엇이 일어나는가)
- 에러/예외 시 사용자에게 보이는 것

### C. 금전 관련 (돈의 흐름)

- 정산/청구/지급에 영향을 주는 규칙
- 재고 차감/복원 시점
- 가격/비용 산정 규칙

### D. 시스템 자동 동작 (사람 개입 없이 일어나는 것)

- 스케줄러/배치에 의한 자동 상태 전이
- 시스템이 자동으로 생성하는 데이터 (자동주문, 정산서 자동 발행 등)
- 자동 알림/사전 안내

## 3. 함의 도출

단순 요약이 아니라, 각 정책의 **실제 결과(implication)**를 `→` 기호와 함께 한 줄로 덧붙인다.

```
[나쁜 예 — 단순 요약]
- 주문 취소는 주문접수 상태에서만 가능

[좋은 예 — 함의 포함]
- 주문 취소는 주문접수(물류 확인 전)에서만 가능
  → 물류센터가 빠르게 확인하면 요양원의 취소 가능 시간이 줄어듦
```

함의는 **이 정책이 사용자·운영·재무에 미치는 실제 결과**를 적는다. 기획 문서의 문장을 그대로 복사하지 않는다.

## 4. 보고 형식

```markdown
## 기획 요약: {페이지명}

> 참조 문서: {메인 문서 경로} 외 N건

### 비즈니스 정책
1. **{정책 제목}**: {정책 요약}
   → {함의}
2. ...

### 사용자 경험

#### 동선

\`\`\`mermaid
flowchart TD
  {진입점} --> {핵심액션} --> {완료/이탈}
\`\`\`

- {동선이 사용자에게 주는 영향/함의}

#### 에러·예외 시 피드백
- **{에러 상황}**: {사용자에게 보이는 것}

### 금전 관련
1. **{규칙 제목}**: {규칙 요약}
   → {재무적 영향}
2. ...

### 시스템 자동 동작
- **{자동 동작명}** (트리거: {조건}, 주기: {빈도/시점})
  → {운영 영향}

### 확인 필요
- {TBD이거나 모호한 사항}
```

### 보고 형식 규칙

- 비즈니스 정책, 사용자 경험, 금전 관련: 해당 항목이 없으면 "(해당 없음)"
- 시스템 자동 동작, 확인 필요: 해당 사항이 없으면 **섹션 자체를 생략**
- 동선은 반드시 mermaid flowchart로 작성한다. 역할(포털)이 2개 이상이면 subgraph로 구분한다
- 도메인 단위 요청 시 페이지별로 반복하되, 공통 정책(상위 문서·공용 문서 유래)은 최상단에 한 번만 보고한다

## 5. 금지 사항

- 파일 수정 금지: 이 스킬은 보고 전용이다
- 구현 세부사항 포함 금지 (API 엔드포인트, DB 스키마, 컴포넌트 구조, 상태 관리 방식)
- 기획 문서의 문장을 그대로 복사하지 않음: 요약하여 정보 밀도를 높인다
- 기획 검토(빈틈/충돌 발견)는 이 스킬의 범위가 아니다
