# 기획 문서 리뷰 가이드

이 문서는 기획 문서를 분석할 때 사용하는 체크리스트, 관련 문서 수집 규칙, 결과 보고 형식을 정의한다.

---

## 1. 관련 문서 수집 규칙

대상 기획 문서와 함께 아래 관련 문서를 읽는다.

- 상위 문서(개요) 1개
- 기획 문서 본문에서 직접 링크로 참조하는 공통 문서. 직접 링크가 없더라도 페이지 유형에 해당하는 공통 정책은 읽는다 (목록 페이지 → 목록과 관련된 공통 정책, 상세 페이지 → 상세와 관련된 공통 정책)
- 해당 페이지와 데이터를 주고받는 형제 문서 (예: 목록↔상세)
- @index.md '공통 문서' 섹션의 문서는 본문에서 참조할 때만 읽는다

## 2. 분석 관점 체크리스트

### 검토 범위

기획 문서는 **"무엇을(What)"** 정의하는 문서다. 검토는 아래 범위 안에서만 수행한다.

| 기획이 다루는 영역 (검토 대상) | 기획이 다루지 않는 영역 (검토 제외) |
|---|---|
| 화면 구성 요소 (필드, 버튼, 테이블 컬럼 등) | API 엔드포인트, 요청/응답 형식 |
| 사용자 동작과 결과 (클릭 시 무엇이 일어나는가) | 서버 구현 방식 (미들웨어, 트랜잭션 등) |
| 비즈니스 규칙, 유효성 검증 조건 | DB 스키마, 테이블 설계 |
| 상태 전이, 조건 분기 | 프론트엔드 컴포넌트 구조, 상태 관리 방식 |
| 에러/예외 시 사용자에게 보여줄 피드백 | 에러 핸들링 구현 패턴 |
| 데이터 표시 형식, 정렬/필터 규칙 | 쿼리 최적화, 캐싱 전략 |
| 권한/역할별 접근 범위 | 인증/인가 구현 방식 (토큰, 세션 등) |

> **원칙**: "이 기획만 읽고 개발자가 화면과 동작을 구현할 수 있는가?"를 판단한다. 세부 구현 방법에 대한 사항은 개발의 영역이므로 부족 사항으로 제시하지 않는다.

### 체크리스트

- [ ] **문서 간 충돌** — 관련 문서(상위 문서, 공통 정책 등)와 내용이 모순되지 않는가?
- [ ] **공통 정책 위임** — 페이지 유형에 해당하는 공통 정책 문서가 존재하는 경우, 해당 문서를 올바르게 참조하고 있는가?
- [ ] **상태 흐름 누락** — 상태 전이, 조건 분기가 빠짐없이 정의되어 있는가?
- [ ] **엣지 케이스** — 대량 데이터, 최대·최소 입력값, 중복 요청, 데이터 정합성 불일치 등 예외 상황이 다뤄져 있는가?
- [ ] **용어 일관성** — 같은 개념에 다른 용어를 사용하고 있지 않은가?
- [ ] **유효성 검증 규칙** — 입력 필드의 필수/선택, 형식, 길이, 범위가 명시되어 있는가?
- [ ] **권한/역할 구분** — 역할별 접근 가능 범위와 동작 차이가 정의되어 있는가?
- [ ] **에러 처리** — 실패 시 사용자에게 보여줄 피드백(토스트, 에러 메시지 등)이 정의되어 있는가?
- [ ] **파괴적 동작 확인** — 삭제, 미저장 이탈, 상태 되돌리기 등 되돌릴 수 없는 동작에 확인 절차(모달 등)가 정의되어 있는가?
- [ ] **로딩/처리 중 상태** — 비동기 작업 진행 중 UI 상태(로딩 표시, 버튼 비활성화, 중복 요청 방지 등)가 정의되어 있는가?
- [ ] **데이터 표시 형식** — 날짜·숫자·금액·전화번호 등의 표시 포맷, 빈 값 표기, 긴 텍스트 처리 규칙이 명시되어 있는가?
- [ ] **사용자 동선** — 진입 경로, 작업 완료·취소 후 이동 목적지, 관련 페이지 연계 흐름이 명확한가?
- [ ] **교차 도메인 정합성** — 동일 기능의 타 도메인 기획과 정합하는가? 각 도메인은 역할에 따라 다른 관점에서 서술하므로, 관점 차이가 아닌 사실 불일치(동일 제약에 대한 다른 값)를 식별한다.
- [ ] **정책 전파 정합성** — 상위/공통 문서에 정의된 정책이 하위/참조 문서에 반영 또는 위임되어 있는가?
- [ ] **데이터 생명주기 추적** — 문서에 정의된 데이터(입력 필드, 첨부 파일, 상태 등)의 생성 → 표시 → 처리 각 단계를 담당하는 기획이 존재하는가?
- [ ] **링크 유효성** — 링크의 대상 파일/앵커가 존재하는가?

## 3. 결과 보고 형식

분석 결과를 아래 형식으로 보고한다.

```
### 분석 결과: {문서 제목}

#### 부족한 사항
1. {구체적 항목} — {왜 부족한지, 어떤 정보가 필요한지}
2. ...

#### 충돌 사항
1. {문서 A의 내용} ↔ {문서 B의 내용} — {어떻게 충돌하는지}
2. ...

#### 확인 필요
1. {판단이 어려운 사항} — {선택지 A vs B}
2. ...
```

- 문제가 없으면 "분석 완료: 부족/충돌 사항 없음"으로 보고한다
- §2 검토 범위 표의 "검토 제외" 열에 해당하는 사항은 보고하지 않는다
