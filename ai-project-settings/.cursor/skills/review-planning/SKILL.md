# 기획 문서 분석

## 1. 기획 문서 탐색

1. `/docs` 하위에 있는 모든 `@index.md`을 읽어 도메인별 목차를 파악한다
2. 사용자 입력과 목차 항목을 매칭한다
   - 계층 구조를 활용한다: "재고 관리 엑셀 일괄 입고" → "재고 관리" 카테고리 → "엑셀 일괄 입고" 항목
3. 후보가 2개 이상이면 `AskQuestion` 툴로 후보 목록을 선택지로 제시하여 사용자에게 확인한다
4. 일치 항목이 없으면 `AskQuestion` 툴로 사용자에게 문서 경로를 직접 요청한다
5. 현재 매칭된 문서와 관련 문서 수집 규칙 [review-guide.md](./review-guide.md) §1에 따라 수집된 관련 문서를 함께 읽는다.

## 2. 분석 관점 체크리스트

[review-guide.md](./review-guide.md) §2의 체크리스트를 읽고, 매칭된 기획 문서에 적용하여 분석한다.

> **주의**: 체크리스트를 수정할 때는 반드시 review-guide.md를 직접 수정한다. 이 파일에 인라인으로 작성하지 않는다.

## 3. 결과 보고 및 처리

[review-guide.md](./review-guide.md) §3의 보고 형식에 따라 분석 결과를 사용자에게 보고한다.

- 부족/충돌 사항이 있으면 보고 후 각 항목에 대해 `AskQuestion` 툴로 처리 방향을 확인한다

### 처리 방향 확인

발견된 각 항목에 대해 `AskQuestion` 툴로 사용자에게 처리 방법을 선택하도록 한다.

- **부족한 사항**: "기획에 추가: {추가할 내용 요약}", "현재는 불필요(Skip)", "추후 결정(TBD)" 중 선택. "기획에 추가" 선택지의 레이블에 구체적인 추가 내용의 요약을 포함하여 사용자가 무엇이 추가되는지 확인한 뒤 선택할 수 있게 한다
- **충돌 사항**: 충돌하는 양쪽 내용을 선택지로 제시하여 어느 쪽을 따를지 선택
- **확인 필요**: 가능한 선택지를 나열하여 사용자가 결정

## 4. 기획 수정 사항 재확인

사용자가 선택한 처리 방법에 대해 추가적으로 정의되어야 하는 사항과 충돌 사항이 다시 생기는지 분석한다.
해당 내역이 있다면 3. 결과 보고 및 처리 단계를 다시 실행하고, 없다면 5. 기획 문서 수정 단계로 넘어간다.

## 5. 기획 문서 수정

사용자가 선택한 처리 방향에 따라 `write-planning` 스킬을 읽고 그 규칙에 따라 기획 문서를 수정한다.
