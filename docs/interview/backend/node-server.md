# Node 런타임 & 서버 기초

> 작성일: 2026-08-26
> 형식: 경량
> 목표: **Node가 싱글 스레드인데 어떻게 여러 요청을 처리하는지 이해한다.**

---

## 1. Node.js는 무엇인가?

Node.js는 **브라우저 밖에서 JavaScript를 실행할 수 있게 해주는 런타임**이다.

```text
Node.js
 ├─ V8
 ├─ Node.js APIs
 └─ libuv
      └─ Event Loop
```

JavaScript 실행은 기본적으로 **싱글 스레드**에서 이루어진다.

---

## 2. 싱글 스레드인데 어떻게 여러 요청을 처리할까?

핵심은 **논블로킹 I/O**다.

DB 조회나 네트워크 요청 같은 I/O 작업을 기다리는 동안 JavaScript 실행을 계속할 수 있다.

```text
Request A
   ↓
DB 요청 ───────────────┐
                       │
Request B              │
   ↓                   │
처리                    │
                       │
Request C              │
   ↓                   │
처리                    │
                       ↓
                  DB 결과 도착
                       ↓
                  A의 작업 계속
```

즉,

> **I/O를 기다리는 동안 다른 요청을 처리할 수 있기 때문에 싱글 스레드에서도 높은 동시성을 만들 수 있다.**

Node의 비동기 I/O 처리에는 **libuv와 OS의 비동기 기능** 등이 사용된다.

---

## 3. 이벤트 루프

Node는 **이벤트 루프를 통해 비동기 작업의 완료를 처리하고 JavaScript 실행을 이어간다.**

```text
I/O 작업 시작
    ↓
다른 작업 처리
    ↓
I/O 완료
    ↓
콜백 / Promise 처리
    ↓
JavaScript 실행
```

브라우저의 이벤트 루프와 기본 원리는 비슷하지만, Node는 **libuv 기반의 이벤트 루프 구조**를 사용한다.

Node에는 `timers`, `poll`, `check` 등의 phase가 있지만, **지금 단계에서는 이름을 외울 필요는 없다.**

---

## 4. CPU 바운드 작업은 예외

CPU를 오래 사용하는 작업은 JavaScript 실행 스레드를 계속 점유한다.

```text
CPU 바운드 작업
      ↓
Event Loop Block
      ↓
다른 요청 처리 지연
```

따라서 CPU 바운드 작업이 필요하다면 **Worker Threads나 별도 프로세스** 등으로 분리할 수 있다.

---

# 핵심 정리

```text
Node.js
   ↓
JavaScript 싱글 스레드
   ↓
논블로킹 I/O
   ↓
Event Loop
   ↓
I/O 기다리는 동안 다른 요청 처리
   ↓
높은 동시성
```

단,

```text
CPU 바운드 작업
      ↓
Event Loop 차단
      ↓
다른 요청 지연
      ↓
Worker 등으로 분리
```

### 면접에서

> **Node는 JavaScript를 싱글 스레드로 실행하지만, I/O를 논블로킹으로 처리하고 이벤트 루프를 통해 완료된 작업을 처리하기 때문에 여러 요청을 동시에 진행할 수 있습니다. 다만 CPU 바운드 작업은 이벤트 루프를 막을 수 있습니다.**

---

## 목표

- Node 이벤트 루프와 논블로킹 I/O를 설명할 수 있다.
- 싱글 스레드에서 동시성이 가능한 이유를 설명할 수 있다.
- CPU 바운드 작업이 이벤트 루프를 막는 이유와 대응 방법을 안다.
