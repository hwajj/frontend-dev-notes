# Node 런타임 & 서버 기초

## 키워드

- **Node 이벤트 루프** — 서버 측 논블로킹 I/O의 핵심. libuv 기반(브라우저 이벤트 루프와 유사·차이).
- **싱글 스레드 + 워커** — CPU 바운드 작업은 이벤트 루프를 막는다. worker_threads/클러스터로 분산.
- **미들웨어** — 요청→응답 사이 체인(Express 등). 인증·로깅·에러 처리.
- **환경변수 / 설정** — `.env`, 시크릿 관리.
- **스트림** — 대용량 데이터를 조각으로 처리.

## 면접 포인트

- **Q. Node가 싱글 스레드인데 어떻게 동시성을 내나?**
  → I/O를 논블로킹으로 위임(libuv)하고 이벤트 루프로 콜백을 처리. CPU 바운드 작업은 오히려 막히므로 워커로 뺀다.
- **Q. 미들웨어 순서가 왜 중요한가?**
  → 요청이 위에서 아래로 흐르며, 인증·body 파싱·에러 핸들러의 위치에 따라 동작이 달라진다. 에러 핸들러는 보통 마지막.
- **Q. 프론트 이벤트 루프(Day15)와 Node 이벤트 루프의 차이는?**
  → 개념은 같지만 Node는 phase(timers/poll/check 등)가 명확하고 `process.nextTick`·마이크로태스크 우선순위가 다르다.

## 목표

- Node 이벤트 루프·논블로킹 I/O를 설명할 수 있다.
- 미들웨어 체인으로 서버 요청 흐름을 구성한다.
- CPU 바운드 작업의 함정과 대응을 안다.
