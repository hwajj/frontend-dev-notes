# Day 48: Custom Hook

## 키워드

- **Custom Hook** — React Hook을 조합해 반복되는 상태 관리·사이드 이펙트 로직을 재사용하기 위한 함수.
- **Hook 규칙** — Custom Hook도 내부에서 다른 Hook을 사용할 수 있지만, Hook은 컴포넌트 또는 다른 Hook의 최상위에서만 호출해야 한다.
- **로직 재사용** — UI를 재사용하는 컴포넌트와 달리, Custom Hook은 **상태와 동작 같은 로직을 재사용**하는 데 초점을 둔다.
- **상태 격리** — 같은 Custom Hook을 여러 컴포넌트에서 호출해도 Hook 내부의 `useState` 등의 상태는 서로 공유되지 않는다.
- **관심사 분리** — 컴포넌트에서 복잡한 상태 관리나 Effect 로직을 분리해 UI 코드를 단순하게 만들 수 있다.

## 질문 예시

- **Q. Custom Hook이란 무엇인가?**
  → 여러 컴포넌트에서 반복되는 **상태 관리나 사이드 이펙트 로직을 함수로 추출해 재사용하는 방법**이다. 이름은 반드시 `use`로 시작해야 하며 내부에서 다른 Hook을 사용할 수 있다.

- **Q. Custom Hook과 일반 함수의 차이는?**
  → Custom Hook은 `useState`, `useEffect`, `useRef` 같은 React Hook을 조합해 **React의 상태와 생명주기에 연결된 로직을 재사용**할 수 있다. 일반 함수는 React의 Hook을 사용할 수 없다.

- **Q. 같은 Custom Hook을 여러 컴포넌트에서 호출하면 상태를 공유하는가?**
  → 아니다. Custom Hook은 **로직을 공유할 뿐 상태 자체를 공유하지 않는다.** 각 컴포넌트가 Hook을 호출할 때마다 독립적인 Hook 상태가 생성된다. 상태를 여러 컴포넌트에서 공유하려면 Context나 Zustand 같은 별도의 상태 공유 방법이 필요하다.

- **Q. Custom Hook을 사용하는 이유는?**
  → 컴포넌트에 들어간 복잡한 로직을 분리하고 여러 곳에서 재사용하기 위해 사용한다. 예를 들어 `useDebounce`, `useFetch`, `useModal`, `useForm`처럼 특정 동작을 추상화할 수 있다.

- **Q. Custom Hook을 만들 때 주의할 점은?**
  → 지나치게 추상화하지 않는 것이 중요하다. 단순히 코드 몇 줄을 함수로 감싸는 것보다 **반복되는 로직과 명확한 책임이 있을 때** 추출하는 것이 좋다. 또한 Hook 내부에서도 React의 Hook 호출 규칙을 지켜야 한다.

- **Q. Custom Hook과 컴포넌트 추상화의 차이는?**
  → 컴포넌트는 **UI를 재사용**하기 위한 것이고, Custom Hook은 **상태와 동작 등의 로직을 재사용**하기 위한 것이다. UI가 동일하지 않더라도 같은 로직을 사용해야 한다면 Custom Hook으로 추출할 수 있다.

## 목표

- Custom Hook의 개념과 **일반 함수와의 차이**를 설명할 수 있다.
- Custom Hook이 **로직은 공유하지만 상태는 공유하지 않는 이유**를 설명할 수 있다.
- 반복되는 상태 관리·Effect 로직을 Custom Hook으로 추출할 수 있다.
- **Custom Hook과 컴포넌트의 역할 차이**를 설명할 수 있다.
- Custom Hook을 과도하게 추상화했을 때 발생할 수 있는 문제를 이해한다.
