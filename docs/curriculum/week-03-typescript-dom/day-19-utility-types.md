# Day 19: Utility Types

## 키워드

- **Partial<T>** — 모든 프로퍼티를 선택적(`?`)으로. 부분 업데이트 객체에 유용.
- **Required<T>** — 모든 프로퍼티를 필수로. `Partial`의 반대.
- **Pick<T, K>** — T에서 K 키만 골라 새 타입 생성.
- **Omit<T, K>** — T에서 K 키를 제외한 나머지로 생성.
- **Record<K, V>** — 키 K, 값 V인 객체 타입. `Record<string, number>`.
- **Readonly<T>** — 모든 프로퍼티를 읽기 전용으로.
- **ReturnType<F>** — 함수 F의 반환 타입을 추출.

## 면접 포인트

- **Q. `Pick`과 `Omit`은 언제 나눠 쓰나?**
  → 남길 키가 적으면 `Pick`, 뺄 키가 적으면 `Omit`이 가독성·유지보수에 유리하다.
- **Q. 유틸리티 타입은 마법인가?**
  → 아니다. 대부분 제네릭 + 매핑 타입(`[K in keyof T]`) + 조건부 타입으로 직접 구현 가능하다. (예: `type MyPartial<T> = { [K in keyof T]?: T[K] }`)
- **Q. `Record<string, T>`의 주의점은?**
  → 존재하지 않는 키 접근도 타입상 통과할 수 있어, 실제로는 값이 `undefined`일 수 있다는 점을 인지해야 한다.

## 목표

- 상황에 맞는 유틸리티 타입을 골라 중복 타입 정의를 줄인다.
- 대표 유틸리티 타입을 매핑 타입으로 직접 구현해 원리를 이해한다.
- API 응답/폼 상태 타입을 유틸리티로 조합해 설계한다.
