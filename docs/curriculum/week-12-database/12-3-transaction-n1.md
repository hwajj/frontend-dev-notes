# 트랜잭션 & N+1

## 키워드

- **트랜잭션 / ACID** — 원자성·일관성·격리성·지속성. 여러 쓰기를 하나로 묶기.
- **격리 수준** — Read Committed / Repeatable Read 등. dirty/non-repeatable/phantom read.
- **데드락** — 서로 락을 기다리다 멈춤. 접근 순서 통일로 예방.
- **N+1 문제** — 목록 1번 + 각 항목마다 1번씩 추가 쿼리. ORM에서 흔함.
- **Eager/Join 로딩** — N+1을 조인/일괄 조회로 해결.

## 면접 포인트

- **Q. 트랜잭션은 언제 쓰나?**
  → "모두 성공 또는 모두 실패"가 필요한 다중 쓰기(예: 결제+재고 차감). 중간 실패 시 롤백.
- **Q. N+1이 왜 성능을 죽이나?**
  → 항목 수만큼 쿼리가 폭증(1+N). 조인·일괄 로딩·DataLoader로 한 번에 가져와야 한다.
- **Q. 격리 수준을 올리면 항상 좋은가?**
  → 아니다. 일관성↑이지만 락·경합↑로 처리량↓. 요구사항에 맞는 수준을 고른다.
