# 연결 & 커넥션 풀

## 키워드

- **커넥션** — 앱↔DB 사이의 연결. 생성 비용이 크다.
- **커넥션 풀** — 연결을 미리 만들어 재사용. 최대 개수 제한이 핵심.
- **풀 고갈** — 반환 안 된 연결이 쌓여 새 요청이 대기/실패(`EMAXCONNSESSION` 등).
- **Session vs Transaction 풀러** — Supabase의 5432(session) vs 6543(transaction pooler).
- **연결 수 ≠ 사용자 수** — 동시 쿼리 수가 기준.

## 면접 포인트

- **Q. 커넥션 풀은 왜 필요한가?**
  → 연결 생성은 비싸다. 풀로 재사용하면 지연↓·안정성↑. 대신 최대 연결 수를 넘기면 대기/에러.
- **Q. 로컬 개발에서 연결이 고갈되는 흔한 원인은?**
  → HMR/중복 인스턴스로 풀이 여러 개 생기거나 연결을 안 닫아서. 싱글턴 풀·정상 종료가 필요.
- **Q. "15개만 연결"이 사용자 15명 제한인가?**
  → 아니다. 동시 "연결" 슬롯 제한이다. 요청은 풀에서 빌려 쓰고 반환하므로 사용자 수와 다르다.
