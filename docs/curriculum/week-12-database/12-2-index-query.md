# 인덱스 & 쿼리 최적화

## 키워드

- **인덱스** — 특정 컬럼 조회를 빠르게(대개 B-Tree). 읽기↑, 쓰기·용량 비용.
- **복합 인덱스** — 여러 컬럼 순서가 중요(좌측 접두 규칙).
- **EXPLAIN** — 쿼리 실행 계획 확인. 풀스캔 여부 진단.
- **카디널리티** — 값의 다양성. 낮으면 인덱스 효과 적음.
- **커버링 인덱스** — 인덱스만으로 쿼리 해결(테이블 접근 생략).

## 면접 포인트

- **Q. 인덱스를 무조건 많이 걸면 되나?**
  → 아니다. 읽기는 빨라지나 INSERT/UPDATE마다 인덱스 갱신 비용·저장공간이 늘어 쓰기가 느려진다.
- **Q. 복합 인덱스 `(a,b)`가 `WHERE b=?`에 안 먹는 이유는?**
  → 좌측 접두 규칙 때문. `a`가 조건에 없으면 인덱스를 못 탄다.
- **Q. 느린 쿼리를 어떻게 진단하나?**
  → `EXPLAIN`으로 실행 계획을 보고 풀스캔·잘못된 인덱스를 찾는다.

## 목표

- 인덱스의 이득과 비용 트레이드오프를 설명한다.
- 복합 인덱스 좌측 접두 규칙을 적용한다.
- EXPLAIN으로 쿼리 성능을 진단한다.
