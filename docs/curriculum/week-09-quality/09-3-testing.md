# 테스트 (단위 · RTL · E2E)

## 키워드

- **테스트 피라미드** — 단위(많이) → 통합 → E2E(적게). 비용·속도 트레이드오프.
- **단위 테스트** — 순수 함수·훅 로직. Vitest/Jest.
- **React Testing Library(RTL)** — "구현이 아니라 사용자 관점"으로 테스트. `getByRole` 우선.
- **E2E** — Playwright/Cypress로 실제 브라우저 흐름 검증.
- **모킹(MSW)** — 네트워크 요청을 가로채 응답 시뮬레이션.

## 면접 포인트

- **Q. RTL이 `getByTestId`보다 `getByRole`을 권하는 이유는?**
  → 사용자가 인지하는 방식(역할·라벨)으로 찾으면 접근성도 함께 검증되고, 구현 변경에 덜 깨진다.
- **Q. 무엇을 단위로, 무엇을 E2E로 테스트하나?**
  → 복잡한 로직·엣지 케이스는 단위(빠름·많이), 핵심 사용자 시나리오(로그인→결제)는 E2E(느림·소수).
- **Q. 왜 MSW로 모킹하나?**
  → 실제 네트워크 계층에서 가로채 컴포넌트/앱 코드를 바꾸지 않고 다양한 응답(성공·에러·지연)을 테스트할 수 있다.

## 목표

- 테스트 피라미드에 따라 테스트 종류를 배분할 수 있다.
- RTL로 사용자 관점 테스트를 작성한다.
- MSW로 네트워크 시나리오를 모킹한다.
