### 모바일 LCP가 느린 진짜 이유

* 모바일 LCP 30초의 주원인은 영상이 아니라 **SPA 구조 + 렌더 차단 CSS + 큰 배경 이미지(CSS background)** 다.
* 모바일에서는 영상을 아예 로드하지 않아 영상은 원인이 아니다.
* `geo-static`은 SEO용 숨김 텍스트라 LCP를 직접 느리게 만들지는 않는다.
* 하지만 사용자에게 보이는 콘텐츠가 HTML에 없고 JS 실행 후에만 나타나는 구조는 LCP에 불리하다.
* 리뉴얼에서는 숨긴 SEO 블록 대신 **시맨틱 HTML(main, h1 등)** 을 실제 화면에 노출하는 것이 좋다.
* SEO는 시맨틱 HTML만으로 끝나는 게 아니라 **서버 렌더링 + metadata + JSON-LD** 가 함께 필요하다.
* LCP 개선의 핵심은 **HTML에 바로 보이는 콘텐츠와 `<img>` 기반 히어로 이미지 제공**이다.



### SPA CSS 충돌·느림, Next로 어떻게 해결하나?

* SPA는 HTML 문서가 하나라서 메인·튜토리얼·챗봇 CSS가 같은 페이지에 동시에 적용될 수 있어 충돌이 난다.
* 그래서 기존에는 `<head>`에 CSS를 미리 등록하고 JS로 필요한 것만 켜고 끄는 방식으로 관리했다.
* 느린 이유는 튜토리얼 CSS 때문이 아니라 메인 CSS의 render-blocking, 큰 JS 번들, 큰 이미지 때문이다.
* CSS 충돌 문제와 성능 문제는 원인은 다르지만 둘 다 SPA 구조에서 나온다.
* Next에서는 route group/layout별로 필요한 CSS만 로드해 충돌과 불필요한 다운로드를 줄일 수 있다.
* 퍼블리셔가 CSS를 전부 새로 만들 필요는 없고 기존 CSS를 어느 layout에 연결할지만 정리하면 된다.
* 결론: Next 전환의 핵심은 "CSS 재작성"이 아니라 "페이지별 CSS 분리 로딩"이다.

### 우분투 배포와 S3는 다른 역할이다

* 홈페이지(HTML·CSS·JS)는 `build → out/ → 우분투 서버`로 배포된다.
* S3는 영상·이미지 같은 큰 파일을 저장하는 별도 저장소다.
* 브라우저는 페이지는 우분투에서 받고, 영상은 S3 URL로 직접 다운로드한다.
* 720p·1080p 같은 영상 파일은 ffmpeg로 만든 뒤 S3에 각각 업로드하면 된다.
* 영상 추가는 우분투 재배포와 별개이며 S3 업로드 권한(IAM)만 있으면 된다.
* 성능 때문에 대용량 MP4는 웹서버보다 S3(+CDN)에 두는 것이 일반적이다.
* 결론: 사이트는 우분투에서 서비스하고, 미디어는 S3에서 제공하는 혼합 구조다.
