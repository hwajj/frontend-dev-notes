# SPA에서 pageview만으로는 퍼널을 못 본다

> 작성일: 2026-06-10
> 맥락: 등록·결제 같은 다단계 화면을 만들었는데, 분석 도구에는 “페이지는 찍히는데 어느 단계에서 이탈했는지”가 안 보인다
> 범위: 로컬 학습 노트 — Git 미공유, 팀 공유 문서에서 참조하지 않음

## 이 글의 질문

- GA4(또는 Mixpanel)에 pageview는 쌓이는데, **등록 퍼널 단계별 이탈**은 왜 안 보이나?
- URL은 바뀌는데 **같은 pathname 안의 하위 단계**(`?step=2`)는 왜 집계에 안 잡히나?
- “다음” 버튼을 눌렀는지, 그냥 탭을 닫았는지 **pageview만으로 구분**할 수 있나?

## 핵심 (먼저 읽기)

| 방식 | 무엇이 보이나 | 퍼널·이탈 분석에 충분한가 |
|------|--------------|--------------------------|
| **pageview (pathname만)** | 주소 경로가 바뀔 때 “페이지 방문” 1건 | 단순 화면 전환만 있으면 **부분적** |
| **pageview + query/hash** | URL 전체를내도록 설정하면 조금 나아짐 | 쿼리를 **의도적으로** 넣은 설계일 때만 |
| **커스텀 이벤트** | 기획 단계·버튼 클릭·이탈을 **이름 붙여** 전송 | 다단계 위저드·폼에 **권장** |

한 줄: pageview는 “주소가 바뀌었나?”를 본다. 퍼널은 “**기획상 단계**가 어떻게 진행됐나?”를 봐야 한다. 둘은 같지 않다.

## 전제 (30초)

- **브라우저**: 사용자가 보는 화면. 주소창 URL이 바뀌면 “다른 페이지”처럼 느껴진다.
- **SPA(싱글 페이지 앱)**: 화면 전환해도 **전체 HTML을 다시 받지 않고** JS가 화면만 갈아끼운다. React + React Router가 흔한 조합.
- **분석 SDK(GA4 등)**: 앱이 “지금 이런 일이 났다”고 서버에 보내는 작은 메시지. **pageview**는 그중 “페이지를 봤다”는 기본 타입.
- **퍼널**: 등록 1단계 → 2단계 → … → 완료처럼 **순서 있는 단계**에서, 각 단계에 몇 명이 남았는지 보는 분석.

## 한눈에

### 경로 A — pageview만 쓸 때 (퍼널 해상도 낮음)

```
사용자: details 화면 (?step=1) → 다음 클릭 → 같은 pathname (?step=2)
분석:   pageview 1건 (pathname=/.../details)  →  pageview 없음 (pathname 안 바뀜)
```

주소 **경로(pathname)** 만내면, 쿼리만 바뀌는 하위 단계는 **한 번도 방문 안 한 것처럼** 보일 수 있다.

### 경로 B — 커스텀 이벤트를 쓸 때 (퍼널 해상도 높음)

```
사용자: details 진입 → step=1 → 다음 → step=2 → 플로우 밖으로 나감
분석:   regist_step_view(step=details, detail_step=1)
        regist_nav(action=next, ...)
        regist_step_view(step=details, detail_step=2)
        regist_abandon(last_step=details)
```

**기획 단계 이름**을 이벤트에 실어내므로, GA4 퍼널·Looker에서 단계별 잔존을 쌓을 수 있다.

## 용어 (이 글에서만)

| 용어 | 한 줄 뜻 |
|------|----------|
| SPA | 한 번 로드한 뒤 JS로 화면만 바꾸는 웹앱 |
| pathname | URL에서 `?` 앞 경로 부분 (`/register/details`) |
| query string | `?step=2&isEdit=true` 처럼 `?` 뒤 파라미터 |
| pageview | “이 페이지를 봤다”는 기본 조회 이벤트 |
| 커스텀 이벤트 | 개발자가 이름·파라미터를 정해 보내는 분석 이벤트 |
| 퍼널 | 단계별로 사용자가 얼마나 남았는지 보는 깔때기 분석 |
| 위저드 | 여러 단계를 순서대로 밟는 등록·설정 플로우 |

## 한 줄 요약

pageview는 **주소 경로 변경**에 맞춰져 있고, 퍼널은 **기획 단계·클릭·이탈**을 봐야 해서 — 다단계 SPA에서는 커스텀 이벤트가 필요하다.

## 함정 한 가지

**“pageview가 찍히니까 추적은 되고 있다”**고 생각하기 쉽다.

실제로는 pathname만내면 **같은 URL 안에서 벌어지는 일**(하위 step, 모달, 탭 전환)은 대부분 빠진다. 대시보드에 숫자가 있어도 **퍼널 질문에 답이 없는** 상태일 수 있다.

## 언제 pageview만으로도 충분한가

다음이면 pageview(또는 화면 전환 이벤트)만으로도 된다.

- 단계마다 **pathname이 반드시 바뀐다** (`/step-1` → `/step-2`)
- 하위 단계가 query가 아니라 **별도 라우트**다
- “다음 버튼”보다 **“몇 번째 화면에 도달했나”**만 보면 된다

반대로 아래가 하나라도 있으면 pageview만으로는 부족하다.

| 조건 | 왜 부족한가 |
|------|------------|
| 같은 pathname + `?step=1\|2\|3` | pathname pageview는 **1번만** 찍힐 수 있음 |
| 클릭(다음/이전)을 행동 지표로 쓰고 싶음 | pageview는 **클릭을 모름** |
| “위저드 밖으로 나감”과 “다음 단계로 진행” 구분 | 둘 다 pathname 변경 패턴이 다를 수 있어 **의도를 이벤트로 박아야** 함 |
| 완료가 다른 앱/플로우로 이어짐 | 중간·최종 전환을 **이름 있는 이벤트**로 잇기 쉬움 |

## 왜 이렇게인가

역사적으로 GA는 **멀티 페이지 웹사이트**를 전제로 했다. 사용자가 링크를 누르면 서버가 새 HTML을 주고, URL이 바뀌면 그걸 “새 페이지 방문”으로 셌다. pageview는 그 모델에 맞는 기본 단위다.

SPA는 화면이 바뀌어도 **문서 단위 로드가 아니라 라우터가 경로만 바꾼다**. 그래서 “페이지”의 정의가 흐려진다. 게다가 기획은 “URL 한 칸 = 화면 한 장”이 아니라 **한 화면 안에 여러 sub-step**을 두는 경우가 많다. 분석 도구의 기본 pageview는 **기획 단계와 1:1이 아니다**.

그래서 실무에서는 (1) pageview에 **전체 URL**을 넣거나, (2) 아예 **커스텀 이벤트로 단계 스키마를 정의**한다. 퍼널·이탈·소요 시간까지 보려면 (2)가 유지보수와 해석 모두 유리하다. pathname만 보내는 구현은 “일단 뭔가 쌓인다”는 안도감을 주지만, **질문에 답하지 못하는 데이터**가 될 수 있다.

## 참고 코드

일반적으로 GA4 + React Router에서는 `useLocation()`으로 경로가 바뀔 때마다 pageview를 보낸다.

이 레포(care 앱)에서는 pathname만 전송한다 — query는 빠진다.

```typescript
// 라우트 변경 시 pageview — pathname만
useEffect(() => {
  ReactGA.send({ hitType: 'pageview', page: location.pathname });
}, [location]);
```

같은 pathname에서 `?step`만 바뀌면 위 effect는 **다시 실행되지 않을 수 있다**(pathname 의존). 설령 `search`를 dependency에 넣어도, GA에 `page`로 pathname만 넣으면 **집계 키에 step이 안 들어간다**.

커스텀 이벤트 쪽은 URL 쿼리를 **의도적으로** 파라미터로 올린다.

```typescript
// query에서 기획 파라미터 추출 → 이벤트에 포함
const detailStep = params.get('step');
if (detailStep) {
  eventParams.detail_step = Number(detailStep);
}
```

라우트 진입은 Tracker가, “다음/이전”은 버튼 핸들러가 맡는 **혼합 패턴**이다. pageview만으로는 불가능한 “명시적 이동”을 `regist_nav`로 채운다.

## 이 레포에서는

| 구분 | 수단 | 한계 / 보완 |
|------|------|-------------|
| 앱 전역 | `GA4Tracker` — pathname pageview | query·하위 step 미반영 |
| 등록 위저드 | `RegistRenewalTracker` + `regist_*` 이벤트 | `regist_step_view`, `regist_abandon`, `regist_nav` 등 |
| 상세 질문지 | URL `?step=1\|2\|3` | pageview로는 구분 어려움 → `detail_step` 파라미터로 전송 |

**이 레포에서 pageview만으로 퍼널을 못 본 이유**: 등록 리뉴얼은 pathname이 단계마다 바뀌는 구간도 있지만, `details`처럼 **한 pathname + query step**인 구간과 **다음 버튼 클릭** 행동이 있다. 기존 `GA4Tracker`는 pathname만 보내서 “몇 단계까지 왔는지·왜 나갔는지”에 답하기 어려웠고, 그래서 커스텀 이벤트 레이어를 추가한 것이다.
